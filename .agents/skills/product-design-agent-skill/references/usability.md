# Clarity and Usability

Use this guide to reduce avoidable cognitive effort.

## Design for incomplete attention

Assume users will often:

- scan rather than read,
- choose the first option that appears good enough,
- skip instructions,
- arrive through deep links,
- operate while distracted,
- use imperfect mental models.

The design should still work.

## Reduce interpretation work

A user should not need to:

- decode labels,
- guess what is clickable,
- infer where information lives,
- remember arbitrary rules,
- distinguish two options that sound almost identical,
- read a paragraph to understand a basic control.

Keep necessary domain thinking. Remove interface-decoding work.

## Make hierarchy functional

Visual structure should reveal:

- what matters most,
- what belongs together,
- what is secondary,
- what can be acted on,
- where the user currently is.

Use spacing, grouping, size, weight, alignment, and placement deliberately.

A quick glance should reveal the page's structure.

## Prefer clear choices over minimal click counts

A slightly longer flow with obvious choices can be better than a short flow filled with uncertainty.

For every decision ask:

- What uncertainty is introduced here?
- Can the label name the actual outcome?
- Can two choices be confused?
- Is there a safe default?
- Can this decision be delayed until it matters?

## Use familiar patterns

Familiar patterns reduce learning cost.

Prefer established interaction conventions for:

- navigation,
- search,
- forms,
- tabs,
- settings,
- menus,
- destructive actions,
- mobile gestures,
- account controls.

Replace a convention only when the alternative is easier to discover and can be validated.

## Cut text that does not help the task

Remove:

- welcome copy,
- internal jargon,
- repetitive descriptions,
- obvious instructions,
- self-congratulatory marketing text,
- copy that exists only to fill space.

Keep text that:

- reduces uncertainty,
- explains consequences,
- supports trust,
- helps comparison,
- supports accessibility,
- helps recovery.

## Preserve orientation

A user landing anywhere in a product should be able to determine:

- what product or area they are in,
- current page or state,
- major sections,
- local context,
- how to go elsewhere,
- where to search when browsing is insufficient.

## Landing-page comprehension

Within seconds, a landing page should make clear:

- what this is,
- who it is for,
- what it helps accomplish,
- why it matters,
- where to begin,
- why it is trustworthy.

## Mobile pressure test

On small screens:

- prioritize the primary task,
- avoid hiding essential context,
- make touch targets forgiving,
- keep controls visible when the keyboard opens,
- use progressive disclosure,
- keep type readable,
- avoid hover-dependent interactions.

## Trust and goodwill

Trust erodes when a product:

- hides necessary information,
- asks for unnecessary data,
- adds unnecessary registration,
- punishes mistakes,
- obscures fees,
- interrupts repeatedly,
- makes leaving harder than joining.

Trust grows when a product:

- anticipates questions,
- explains consequences,
- saves work,
- preserves user input,
- admits limits,
- makes recovery easy,
- respects the user's time.

## Fast clarity audit

Ask:

1. What is this page for?
2. What is the main action?
3. What can be clicked?
4. Where am I?
5. What would you choose to complete the main task?
6. What do you expect to happen next?
7. What looks unnecessary?
8. What would you ignore?

Slow or inconsistent answers indicate avoidable cognitive load.
