# Product Design Audit Checklists

Use only the sections relevant to the product.

## Product and value

- [ ] Primary user is explicit.
- [ ] Primary job is explicit.
- [ ] Product solves a real problem.
- [ ] Value appears before major commitment.
- [ ] Business metric maps to user value.
- [ ] Rare-use products are not forced into fake engagement loops.

## Information architecture

- [ ] Main sections match user mental models.
- [ ] Labels are concrete and distinct.
- [ ] Current location is visible.
- [ ] Deep links preserve orientation.
- [ ] Search exists when browsing alone is insufficient.
- [ ] Similar actions are grouped.
- [ ] Technical architecture does not leak unnecessarily into navigation.

## Visual hierarchy

- [ ] One clear primary action.
- [ ] Heading hierarchy is obvious.
- [ ] Related content is grouped.
- [ ] Interactive elements look interactive.
- [ ] Important status is visible without close reading.
- [ ] Decorative content does not compete with task content.
- [ ] Text is readable and sufficiently contrasted.

## Forms

- [ ] Ask only for necessary data.
- [ ] Labels persist.
- [ ] Requirements appear before submission.
- [ ] Validation is specific and local.
- [ ] User input survives errors.
- [ ] Defaults are safe.
- [ ] Optional fields are clearly optional.
- [ ] Sensitive-data collection is justified.

## Interaction

- [ ] Possible actions are discoverable.
- [ ] Feedback is immediate and meaningful.
- [ ] State changes are visible.
- [ ] Controls map predictably to outcomes.
- [ ] Constraints prevent invalid actions.
- [ ] Common actions are easy.
- [ ] Advanced controls do not overwhelm novices.
- [ ] System status is visible.

## Error design

- [ ] Destructive actions name the object affected.
- [ ] Undo or recovery exists where feasible.
- [ ] Duplicate submissions are prevented.
- [ ] Offline or network failure is handled.
- [ ] Empty states explain how to proceed.
- [ ] Permission denial has a recovery path.
- [ ] Errors explain what happened and what to do next.

## Mobile

- [ ] Primary task remains visible.
- [ ] Tap targets are usable.
- [ ] Essential information is not hover-dependent.
- [ ] Keyboard does not obscure critical controls.
- [ ] Long forms are staged.
- [ ] Navigation is recoverable.
- [ ] Layout works at narrow widths and with zoom.

## Accessibility

- [ ] Keyboard operable.
- [ ] Logical focus order.
- [ ] Visible focus.
- [ ] Sufficient contrast.
- [ ] Text alternatives where relevant.
- [ ] Inputs have labels.
- [ ] Errors are associated with the relevant control when applicable.
- [ ] Meaning is not conveyed only by color.
- [ ] Motion can be reduced where needed.
- [ ] Zoom and text scaling do not destroy the layout.

## Onboarding

- [ ] User reaches value quickly.
- [ ] Product does not explain what can be learned by doing.
- [ ] Permissions are requested in context.
- [ ] Setup is progressive.
- [ ] Sample data is used when it reduces blank-state confusion.
- [ ] Skip is available for nonessential setup.
- [ ] Success is explicit.

## Repeat use

- [ ] Recurring user need exists.
- [ ] Cue maps to that need.
- [ ] First useful action is easy.
- [ ] Outcome resolves the need.
- [ ] Repeat use creates user-owned future value.
- [ ] Notifications are permissioned and relevant.
- [ ] Natural stopping points exist where appropriate.
- [ ] No dark patterns.
- [ ] Cancellation and deletion are straightforward.
- [ ] Retention metric is tied to value, not raw attention.

## Trust

- [ ] Prices and recurring charges are obvious.
- [ ] Permissions explain why they are needed.
- [ ] Defaults are not deceptive.
- [ ] Ads or sponsored content are distinguishable.
- [ ] Data controls are understandable.
- [ ] Export, delete, and cancel actions are findable.
- [ ] Product does not fake scarcity, urgency, or social proof.

## Final audit output

Return:

- score by relevant category from 1 to 5,
- top three strengths,
- top five problems,
- severity,
- exact recommendation,
- expected user impact,
- evidence or assumption,
- validation method.
